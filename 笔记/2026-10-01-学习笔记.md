## 1. Pi Agent 学习入口：费曼冬瓜讲述

记录日期：2026-10-01  
状态：已找到配套教程、源码仓库与 Skill；原始视频链接仍待补充

### 为什么先看这个讲解

完成 Agent Memory Challenge 后，计划继续学习开源的 Pi Agent，并以此理解一个成熟 Agent 项目的工程结构，最终搭建面向工业/CAD场景的生产级 Agent。

费曼冬瓜的讲解被选作学习入口，不是为了只会使用 Pi，而是为了先获得一张源码阅读地图，再进入官方文档和代码仓库。

### 观看时重点关注的三个问题

截图中的三个主题是：

1. 如何维护 Agent 的循环：Trace、Turn、大事件钩子；
2. 如何进行上下文管理：截断、压缩、缓存命中率；
3. 如何维护工具调用：四阶段管道、错误回暖或错误恢复。

建议观看时不要只记录名词，而要追踪一条完整执行链：

```text
用户消息
  → 构造本轮上下文
  → 请求模型
  → 模型产生工具调用
  → 校验并执行工具
  → 写入工具结果
  → 再次请求模型
  → 形成最终回复或继续循环
```

### 需要从 Pi Agent 学到的内容

#### Agent 循环

- 一轮模型请求在什么条件下继续或终止；
- 工具调用如何进入下一轮上下文；
- 如何限制最大步数、超时和费用；
- 用户如何中途修正或打断任务；
- 异常后如何恢复而不是丢失整条任务。

#### Trace 与 Turn

- Turn 是一次用户、模型或工具交互单元；
- Trace 是一次完整任务的执行轨迹；
- 事件钩子用于记录模型调用、工具开始、工具结束、错误与状态变化；
- Trace 后续可以用于调试、评测、审计和失败案例复盘。

#### 上下文管理

- 哪些消息必须保留原文；
- 哪些内容可以压缩；
- 工具输出过长时如何截断；
- 如何在压缩后保留任务目标、关键事实和未完成事项；
- 缓存如何降低重复模型调用和相同输入的处理成本。

#### 工具系统

- 工具 schema 如何定义；
- 参数如何校验；
- 工具是否具有读取、写入或高风险权限；
- 执行结果如何标准化；
- 超时、重试、幂等和人工审批如何实现。

### 不直接照抄 Pi 的原因

Pi 更适合作为 Agent 工程的参考骨架，不应被误认为开箱即用的工业生产系统。工业 Agent 还需要补齐：

- 用户身份与数据隔离；
- 最小权限和高风险操作审批；
- 日志、链路追踪、成本监控；
- Prompt Injection 与恶意文档防护；
- 重试、幂等、队列和任务恢复；
- 离线评测集与版本回归；
- 模型降级、服务熔断和密钥管理；
- CAD操作前后的几何及工程约束校验。

### 与后续工业 Agent 的关系

计划中的工业/CAD Agent 可以形成如下闭环：

```text
用户需求、图纸、CAD模型
          ↓
Agent任务规划与知识检索
          ↓
调用特征识别、CAD生成等专业工具
          ↓
CAD内核执行与几何验证
          ↓
失败诊断、修改计划、重新执行
          ↓
输出模型、证据、执行轨迹和人工确认点
```

## 2. Agent 循环、上下文管理、长期记忆与工具调用

记录日期：2026-10-01

### 核心结论

上下文管理与 Agent Memory Challenge 关联很大，但二者不是同一个概念：

> 上下文管理决定模型这一轮看到什么；长期记忆决定跨越多轮和长时间后，系统应该保存、更新和找回什么。

完整的记忆 Agent 至少包含三层：

```text
第一层：Agent循环
Trace、Turn、事件、异常、重试、工具调用

第二层：上下文管理
分段、压缩、截断、预算、缓存、证据编排

第三层：长期记忆
写入、更新、冲突、遗忘、检索、重排
```

比赛主要通过 Add/Search 评价第三层，但第三层效果高度依赖前两层。

### 四个概念的边界

#### Agent 循环

Agent 循环控制系统怎样反复执行：

```text
接收目标
  → 调用模型
  → 产生工具调用
  → 执行工具
  → 观察结果
  → 更新状态
  → 继续行动或结束
```

它关心控制流、终止条件、错误恢复和执行状态。

#### 上下文管理

上下文管理控制下一次模型请求携带的内容，包括：

- 当前任务目标；
- 最近对话；
- 工具调用与关键结果；
- 从长期记忆中检索出的证据；
- 系统规则与权限；
- 当前剩余 token 预算。

它关心的是有限窗口中的信息选择与编排。

#### 长期记忆

长期记忆保存不能始终放在上下文窗口里的历史信息，包括：

- 原始对话和图像；
- 事件摘要；
- 稳定事实和用户偏好；
- 信息更新、冲突和撤回；
- 已完成任务的经验与结果。

它关心跨会话、跨任务的信息持续性。

#### 工具调用

工具调用使 Agent 能够接触模型之外的世界，例如：

- 向量数据库和关键词检索；
- OCR和视觉模型；
- reranker；
- 文件与数据库；
- CAD API和几何内核；
- 评测器和部署服务。

它关心能力执行、权限边界和结果反馈。

### 与比赛 Add 的关系

比赛的 Add 不是简单地把每条消息分别向量化。对于一段图文历史，需要处理：

- Turn 是否属于同一事件；
- 图片、caption和后续纠正如何绑定；
- 新事实是新增、修改、冲突还是撤回；
- 哪些内容值得形成长期记忆；
- 原始记录、摘要和结构化事实如何共同保存。

推荐的分层存储：

```text
原始记录层
├─ 原始Turn
├─ 原图
└─ 官方caption

事件层
├─ 事件摘要
├─ 时间范围
└─ 参与实体

事实层
├─ 事实内容
├─ 来源
├─ 有效时间
├─ 置信度
└─ 当前状态

检索层
├─ 文本Embedding
├─ 图像Embedding
├─ 关键词
└─ 元数据索引
```

### 与比赛 Search 的关系

Search 应完成的链路：

```text
用户问题
  ↓
查询理解与改写
  ↓
文本、图像、关键词等多路召回
  ↓
去重、时间过滤与冲突处理
  ↓
重排
  ↓
上下文预算分配
  ↓
返回有限、相关、可追溯的证据
```

上下文管理决定：

- 返回多少条证据；
- 返回原文、摘要还是两者组合；
- 是否保留相邻 Turn；
- 图片证据占用多少预算；
- 多跳问题如何组合多个事件；
- 新旧事实冲突时怎样排序和标注。

### 截断、压缩与长期记忆

简单截断：

```text
窗口过长 → 删除最早消息
```

这对长期记忆任务很危险，因为问题可能询问很久以前的信息。

更合理的方式是：

```text
原始数据完整保存
      ↓
事件级压缩
      ↓
事实与关系提取
      ↓
Search时按问题选择合适粒度
```

不同问题应返回不同层次：

- 精确原话问题：原始 Turn；
- 长期偏好问题：结构化事实；
- 事件经过问题：事件摘要和相邻记录；
- 图片内容问题：图片、caption、OCR和视觉描述；
- 信息变化问题：带时间的多个事实版本。

### 缓存与多模态记忆

图片处理成本较高，可按内容哈希缓存：

```text
image_hash
├─ 官方caption
├─ OCR结果
├─ 视觉模型描述
├─ 图像Embedding
└─ 处理模型与版本
```

还可以缓存查询 Embedding、query rewrite和候选集合。但缓存必须绑定版本和记忆状态，避免信息更新或删除后仍返回陈旧结果。

### 工具调用如何服务记忆系统

一次 Search 可能调用多个工具：

```text
查询解析器
  → 向量检索
  → BM25检索
  → 图像检索
  → 元数据过滤
  → Reranker
  → 证据打包器
```

每个工具需要记录：

- 输入和输出 schema；
- 开始、结束和耗时；
- 超时和错误类型；
- 是否可以重试；
- 结果来源和版本；
- 是否命中缓存。

这些 Trace 是后续做错误分析和评测的基础。

### 国庆 baseline 的合理范围

第一版不追求完整的自动记忆治理，优先完成：

1. 保留原始 Turn 和图文顺序；
2. 图片与 caption 正确绑定；
3. 同时索引原文、caption和事件摘要；
4. Search 后进行重排并限制证据预算；
5. 记录 Add/Search 的完整 Trace；
6. 对图片描述和 Embedding 做内容哈希缓存；
7. 用固定小型评测集测试召回、冲突和图文问题。

第一版的完成标准：

> 原始记录不丢失，重要信息能够压缩，问题相关的文字或图片证据能够准确进入有限上下文。

### 与后续工业 Agent 的迁移

竞赛中形成的模块可以直接迁入工业 Agent：

- Trace：用于生产调试和审计；
- Turn与事件聚合：用于长任务状态管理；
- 长期记忆：用于积累用户偏好、项目知识和历史案例；
- 上下文预算：用于控制成本与稳定性；
- 工具管道：用于接入 CAD、数据库和企业系统；
- 证据来源：用于工业场景中的可信回答与责任追踪。

因此，本次比赛并不是与工业 Agent 分离的一次练习，而是在训练其中的记忆、上下文和评测子系统。

## 3. Pi Agent 二次开发教程与 dg-piagent Skill

记录日期：2026-10-01  
来源作者：冬瓜（GitHub：`buchidonggua`）

### 资源入口

- 在线教程：<https://dg-ai-notes.pages.dev/>
- GitHub 仓库：<https://github.com/buchidonggua/dg-ai-notes>
- `dg-piagent` Skill：<https://github.com/buchidonggua/dg-ai-notes/tree/main/skills/dg-piagent>
- Pi 官方网站：<https://pi.dev/>

### 资源定位

该项目是围绕 Pi Agent 的双轨教程：

1. 源码学习：10章拆解 Agent SDK 的核心设计；
2. 实战上手：7章完成一个可以封装成服务的垂直 Agent；
3. Skill 应用：通过 `dg-piagent` 为 AI 助手提供 Pi SDK 的开发参考和场景手册。

它非常适合作为比赛结束后学习 Pi 二次开发的主教材，但不替代 Pi 官方文档和当前源码。教程中的 API、包名和行为需要与实际安装版本再次核对。

### 源码学习路线

教程的10章源码线索为：

1. 为什么 Pi Agent 值得学习；
2. Pi Agent 的三层架构；
3. Agent Loop；
4. 多模型调用；
5. 工具系统；
6. 消息系统；
7. 事件驱动；
8. 上下文工程；
9. 上下文压缩；
10. 会话管理、恢复与分叉。

与当前 Agent Memory Challenge 关系最直接的是第6、8、9、10章；与后续工业 Agent 工程化关系最直接的是第3、5、7章。

### 二次开发实战路线

教程的7章实战线索为：

1. 环境部署；
2. 核心 API 与三层架构；
3. 模型配置和企业内网模型接入；
4. 系统提示词覆盖；
5. 工具定义；
6. 事件监听与个性化逻辑；
7. 将 Agent 封装成服务并准备上线。

教程使用企业数据分析助手 DataAgent 作为垂直案例。学习时应先跟随案例跑通，再将其数据工具替换成记忆检索、CAD API、几何验证和工业知识库工具。

### dg-piagent Skill

仓库中提供 `skills/dg-piagent/`，结构包含：

```text
dg-piagent/
├─ SKILL.md
└─ references/
```

README说明该 Skill 从两个视角组织：

- SDK 功能视角：用于查询 Pi Agent API和机制；
- 场景应用视角：用于按需求选择上下文注入、事件监听、工具设计等实现方案。

作者说明其 API 核对到 `pi-coding-agent v0.83.0`。这是一项重要的版本边界：以后使用 Skill 时，必须先确认当前 Pi 版本，检查已经变更、废弃或新增的 API。

### 与比赛的直接关联

#### 消息系统

帮助理解 Turn、模型消息、工具调用结果如何进入 Agent 状态。

#### 上下文工程

帮助决定从长期记忆 Search 得到的证据，如何被编排进本轮模型输入。

#### 上下文压缩

帮助处理超长会话，但不能替代比赛中的长期记忆写入、更新、冲突和检索。

#### 会话管理

帮助保存、恢复和分叉任务轨迹，可用于比赛调试和失败案例复现。

#### 事件监听

可用于记录 Add/Search、Embedding、OCR、Rerank、缓存命中和异常恢复等 Trace。

### 与工业/CAD Agent 的迁移方式

先跟随教程完成 DataAgent，再逐步替换工具：

```text
DataAgent工具                工业/CAD Agent工具
------------------------------------------------
SQL查询                  →   工业知识库检索
数据分析                 →   特征识别模型
图表生成                 →   CAD模型/工程报告生成
危险SQL拦截              →   高风险CAD修改审批
数据校验                 →   CAD内核与几何约束校验
业务日志                 →   设计过程Trace与审计
```

最终希望形成：

```text
Pi Agent编排层
├─ 对话与上下文管理
├─ 工具调用
├─ 事件与Trace
├─ 会话恢复
└─ 权限与审批扩展
        ↓
Python专业服务层
├─ 多模态记忆
├─ RAG与重排
├─ CAD特征识别
├─ CAD序列生成
└─ 几何执行与验证
```

### 推荐学习顺序

1. 当前阶段先完成 Agent Memory Challenge，不立即安装或深挖 Pi；
2. 比赛结束后完成实战P01-P07，跑通 DataAgent；
3. 阅读源码M01-M03，掌握三层架构和 Agent Loop；
4. 阅读M05-M10，重点关注工具、消息、事件、上下文和会话；
5. 审查并试用 `dg-piagent` Skill；
6. 用 Python重写一个最小 Agent Loop，确认真正理解；
7. 将竞赛的记忆系统作为工具接入；
8. 最后搭建工业/CAD垂直 Agent。

### 使用 Skill 前的安全与质量检查

目前只记录资源，不自动安装。正式使用前需要：

1. 完整阅读 `SKILL.md`；
2. 检查 `references/` 中是否包含过期 API；
3. 检查是否包含脚本、命令、网络访问或文件写入要求；
4. 将其声明的 Pi 版本与当前安装版本比较；
5. 优先用项目级安装，避免一开始污染全局环境；
6. 先在实验项目中验证，再用于正式工业 Agent；
7. 遇到 Skill 与官方文档冲突时，以当前官方源码和文档为准。

### 当前判断

该资源值得作为后续 Pi Agent 学习主线。它提供的价值不只是教程，而是把“源码理解—二次开发—Skill辅助”连接成了一条完整路线。我们应当把它视为高质量的学习和开发参考，而不是未经验证的永久真相。
