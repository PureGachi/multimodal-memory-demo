# 2026-10-13 学习笔记

## 思路：先安装并验证本地 OCR

用户选择先安装本地 OCR，而不是接付费视觉模型。继续使用项目的 Conda 环境 `.conda` 和已有 TesseractAnalyzer，不新增在线服务、不上传用户图片，不改现有业务数据库。

### 安装结果

通过 conda-forge 安装 Tesseract 5.5.1（build h86caa34_0），语言数据随包安装，包括 `chi_sim`、`eng` 和其他语言。程序位于 `.conda/Library/bin/tesseract.exe`，语言文件在 `.conda/share/tessdata`。执行版本检查和指定目录的语言列表检查成功。

安装时先 dry-run 核对：增加 OCR 及原生库依赖，不替换原有 Python 或 OpenSSL。实际采用 `--freeze-installed` 并固定已有 `openssl=3.5.9`，下载约 172.7 MiB。依赖没有写进 pip 的 requirements-lock，因为它们由 Conda 管理。

安装源最初遇到 SSL EOF。只对安装子进程移除代理环境变量后连接正常，保留 HTTPS 验证，没有关闭证书校验、修改全局代理或更换全局 Conda 源。可复用的安装形式：

```powershell
conda install --prefix .\.conda --override-channels -c conda-forge tesseract=5.5.1 --freeze-installed
```

其他机器安装前同样先检查 dry-run；不能保证不同环境会得到完全相同依赖。此次为保持本机已有 OpenSSL，另加了 `openssl=3.5.9` 约束。

## 发现的问题与修复

### 1. 安装成功不等于语言目录配置正确

不激活环境、直接运行完整 exe 路径时，Tesseract 默认没找到 Conda 的语言文件，第一次 Add 因 OCR 子进程失败而报错。修复 `vision/ocr.py`：尊重显式 `TESSDATA_PREFIX`；未设置时从 Conda exe 位置找到 share/tessdata，调用时明确传入 `--tessdata-dir`。记录目录到分析版本与 provenance。新增两项回归检查，覆盖自动定位与显式覆盖。

### 2. 同时启用两种语言不保证更准确

对清晰设备测试图做真实对照：

| 语言配置 | “冷却水泵”的实际 OCR |
| --- | --- |
| chi_sim+eng | SHAR |
| eng+chi_sim | SHAR |
| chi_sim | 冷却水泵 |

chi_sim 同时正确读出示例中的 M42，K88，T17。因此本轮启动脚本默认 chi_sim，英文模型也已安装；纯英文资料可试 eng，混合资料按实际图片对照，不默认认为语言越多越好。

第一轮混合语言虽然搜索“冷却水泵”也找回了目标消息，但并非读对设备名：OCR 的其他句子保留“水位”，BM25 可能依靠局部文字重合命中。新增报告字段检查目标查询文字是否确实出现在 OCR 中，防止把 top1 正确误当成转录准确。

## 新工具与使用方式

新增 `scripts/enable_ocr.ps1`，只设置当前 PowerShell 会话的 OCR 配置：明确 exe、语言目录、chi_sim，并关闭远程视觉。不修改系统环境变量或用户 shell 配置，不改变 MEMORY_EMBEDDINGS。开启方式：

```powershell
. .\scripts\enable_ocr.ps1
# 可选：先不用 Ollama，单测 OCR + BM25
$env:MEMORY_EMBEDDINGS = 'none'
```

再按 README 启动 API，或运行 `scripts/inspect_image.py --image 你的图片.png --query 你的问题`。已有正在运行的服务不会自动切换配置；要在上述同一终端重新启动才生效。旧图片不会自动补 OCR，需要明确运行 backfill 工具。

新增 `scripts/ocr_smoke.py`：程序绘制三张清晰文字图，只上传原图，使用真实 Tesseract 与 BM25，临时数据库中混合查找，再保存图片与 Markdown/JSON 报告；不调用 embedding 或付费 API。

```powershell
.\.conda\python.exe -X utf8 scripts\ocr_smoke.py
# 比较两种语言组合的识别，可追加 --languages chi_sim+eng
```

## 实测结果与边界

最终报告：[真实 OCR 与检索结果](../data/evaluations/ocr/20261013T134907Z-be624ab9/report.md)。

- 三个查询“冷却水泵”、K88、T17 的目标文字被识别，均首条返回正确图片，原图字节一致。
- 无证据查询 ZXQ999_NOT_FOUND 返回空。这里只验证这个例子的 BM25 行为，不代表实现通用拒答。
- 设备型号 M42 与中文设备名正确识别；采购图顶部“采购记录”未出现在 OCR 中，说明即使清晰大字也可能漏行，不能宣称全部文字识别无误。
- 全部 63 项自动检查通过（此前 61 项加目录定位的两项）。真实单图 inspect_image 工具也跑通。
- 此处是三张程序绘制、白底大字、无遮挡图片，不是自然拍摄样本或准确率基准。没有验证模糊、小字、旋转、表格、复杂背景，也没有运行真实图像的向量检索或 HTTP OCR smoke。
- OCR 只提供文字信息，不能识别没有文字的颜色、物体与场景；远程视觉效果仍未验证。

参考：[conda-forge Tesseract 包](https://anaconda.org/conda-forge/tesseract)、[Tesseract 安装与语言数据说明](https://tesseract-ocr.github.io/tessdoc/Installation.html)。

## 工作台图文报告与兼容修复

随后用户希望在工作台直接看报告中的图片。已接入 data/evaluations/ocr 和 images 报告，保留原 Mem-Gallery 报告；同一报告选择框可切换图文与文字报告。新增报告图片接口，仅允许读取报告明确引用、位于该报告目录内、校验通过的 PNG/JPEG/WebP，不读取任意绝对路径、不加载外部网址。

新 OCR 报告保存实际召回卡片的图片引用、排名、分数与派生文字。旧 OCR 报告仅有 returned_ids 时，用同份报告里的消息 ID 映射对应图片，并明确说明旧报告未记录分数。新单图 inspect 报告复制图片到报告目录，避免依赖用户原文件的绝对路径；旧单图报告无可读副本时提示重新生成。现有 Mem-Gallery 报告不包含原图，页面升级不会凭空补出图片。

用户随后报告 `Cannot read properties of undefined (reading 'scenario')`。检查当前服务：图片报告有正确 report_type、没有文字报告的 metadata，工作台没有运行中的任务。旧页面如果只“刷新列表”而不重载 JavaScript，会仍按文字报告读取 metadata.scenario；目前证据与此相符，但没有浏览器错误堆栈，不能完全断言唯一原因。

修复：页面按 samples / image_artifacts 兼容识别旧报告，不再盲读 metadata；格式未知时给出明确提示；HTML 和 API fetch 禁用缓存，页面标题增加“图文报告版”以便确认版本。新增 Node 最小 DOM 前端回归，实际执行页面脚本检查旧 OCR、旧文字、非法报告三种路径。全套 72 项测试通过。已在确认无运行任务后重启工作台，用户需要 Ctrl+Shift+R 刷新整个页面，而不是只点“刷新列表”。

图文接入时用真实 OCR 生成了 20261013T141601Z-2551a7b1 报告，并在线确认三张图片接口均返回 200。浏览器视觉实查曾因 computer-use 无法确定当前浏览器 URL 而被安全终止，未宣称截图验收通过；此次兼容修复也仅作接口与前端脚本验证。
