# 2026-10-15 学习笔记：参赛模型配置与 OpenAI SDK

## 思路：哪些步骤需要模型？

用户希望按官方指定模型准备参赛，并指出：不是每一步都需要 GPT，主要是在识图、以及未来从对话提取结构化记忆时使用。

这个理解是对的。当前图片理解是可选的 LLM 调用；对话结构化提取尚未实现。分片、BM25、RRF、SQLite 和图片文件保存不需要 LLM。Embedding 是独立的模型调用，不应改成 GPT。

官方 FAQ 当前指定学术榜 Embedding 使用 `text-embedding-v4`、LLM 相关组件使用 `gpt-4o-mini`。网页同时存在“开源方法榜”等不同名称，最终适用组别、OCR 是否允许和中转渠道是否接受，需要向主办方确认，配置校验并不等于官方合规认证。

参考：[赛事 FAQ](https://agentmemories.ai/competition/)。

## 结果：增加参赛配置，保留本地方案

- 本地默认继续使用 Ollama/nomic，方便不付费调试。
- `embeddings/compatible.py` 新增 `text-embedding-v4` API 适配：每批最多 10 条、默认 1024 维、校验并归一化、按响应 index 恢复顺序、不加 nomic 前缀、不自动重试。
- `embeddings/factory.py` 按配置装配本地或远程 embedding；主程序和两个评测脚本使用此入口。
- `MEMORY_PROFILE=competition` 在启动前检查指定模型、服务鉴权；暂关闭本地 OCR，属于保守选择，不表示官方明令禁止 OCR。
- `.env.competition.example` 只是示例，不会自动加载；`scripts/enable_competition.ps1` 配置当前终端，密钥需单独私下设置。
- 参赛配置默认写入 `data/competition`，旧向量不会自动转换。重新导入资料时生成新模型向量；重复已有 request_id 不会补建向量。
- Mem-Gallery CLI 支持 `--embeddings env`、`--image-analysis configured`。工作台按钮仍是本地 BM25/Ollama/OCR 路线，不能把其结果当成参赛模型结果；CLI 生成的新报告仍可在工作台展示。

参考：[阿里云 embedding API](https://www.alibabacloud.com/help/zh/model-studio/text-embedding-synchronous-api)。

## 思路：改用官方 OpenAI Python 库连接

用户提供 `openai.chat.completions.create(...)` 示例，希望用 OpenAI SDK 连接图片描述模型。采用独立 `OpenAI(...)` 客户端，而不是修改模块级全局密钥与 URL，避免不同客户端相互影响。

原本就是 Bearer 认证，不缺 Codex 的 `requires_openai_auth` 配置。此前博客讨论 Codex 工具，不是本项目 Python 的图片请求，不能直接套用。

## 结果：只替换连接层，不改变检索架构

`llms/compatible.py` 改用 `client.chat.completions.create(...)`：

1. 原有图片仍编码为 Base64，和图片分析提示词一起发送。
2. 返回文本仍交给 `CaptionAnalyzer` 解析及校验 description/visible_text。
3. 图片描述仍用于文本索引，搜索仍返回原始消息和原图。

SDK 安装到项目 `.conda`：`openai==3.31.0`，依赖写入 pyproject 与 requirements-lock。Embedding 适配器不在此次 SDK 替换范围内，仍使用 HTTP 调用。

保留 90 秒超时、不读取环境代理、禁用 SDK 自动重试（`max_retries=0`），每次请求后关闭客户端。没有添加示例中的 `x-foo`，它不是 OpenAI 官方要求的请求头。

密钥仍来自 `VISION_API_KEY`，不写源码或笔记。错误只显示 HTTP 状态和白名单中的错误代码，例如 `insufficient_quota`；未知代码显示 `unclassified`，不显示上游正文，也不串联可能包含隐私的 SDK 异常。

参考：[OpenAI Python SDK 官方说明](https://developers.openai.com/api/reference/python/)。

## 怎样试一张图片

在已经配置密钥的同一个 PowerShell 中执行，以下示例不包含真实密钥：

```powershell
$env:MEMORY_PROFILE = 'local'
$env:MEMORY_EMBEDDINGS = 'none'
$env:MEMORY_OCR = 'none'
$env:MEMORY_VISION = 'compatible'
$env:VISION_BASE_URL = 'https://api.openai.com/v1'
$env:VISION_MODEL = 'gpt-4o-mini'
# VISION_API_KEY 由你在本机私下设置；中转服务需要其自己的地址和密钥。
.\.conda\python.exe -X utf8 scripts/inspect_image.py `
  --image "data/evaluations/ocr/20261013T134726Z-8cd08dfe/equipment.png" `
  --query "M42冷却水泵" `
  --allow-remote
```

这是 GPT 图片分析 + BM25 的单图链路检查，不是准确率测试，不使用参赛 embedding。成功生成的报告可在工作台刷新列表后查看。

仅设置环境变量不会付费，执行真实 API 请求可能计费。ChatGPT Plus 与 API 单独计费；创建密钥不等于已有额度。之前用户真实测试返回 HTTP 429，尚未取得具体错误代码，不能认定一定是限速或余额不足；换 SDK 也不解决账户额度问题。
