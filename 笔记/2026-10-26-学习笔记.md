# 2026-10-26 学习笔记

## 思路：Docker 装好以后，自动补齐能在本地完成的验收

用户希望自动执行、测试、修复并持续推进。范围是本地构建与部署准备，不调用新的付费模型、不租机、不开放公网、不删除现有数据、不自动推送新版本。
Docker 已由用户安装；实测程序在 `D:\Apps\Docker`，WSL 数据磁盘在 `D:\Apps\DockerData`。镜像、构建缓存和导出归档仍会额外占空间，不能只算程序本身体积。

“代码能在 Conda 跑”和“安装到 Linux 镜像能跑”是两份证据；“本地容器通过”和“正式服务器及官方通过”也必须分开记录。

## 实现与修复

- 构建 Linux amd64 生产镜像，锁定依赖能安装。发现构建白名单漏掉 MIT 文件，补齐 Dockerfile COPY 与 .dockerignore 里的 LICENSE。
- 提取 `_http_checks.py`，让原本机进程验收和新 Docker 验收共用同一套受控 HTTP 断言，不复制另一套业务或测试规则。
- 新增 `docker_smoke.py`：假数据、非 root、安装后的包、图片还原、鉴权、预算、隔离、容器重建同卷持久化、pip check 和健康检查；参赛模式只测启动/校验/空 K，不做模型推理。
- 最初将禁止外网的 internal 网络与宿主机端口映射同时使用，Docker 没有分配发布端口，导致测试工具失败；不是 Add/Search 崩溃。改为主流程在隔离容器内发真实 HTTP，再另用关闭模型的容器测试 127.0.0.1 映射。没有放宽生产鉴权或改变模型规则。
- 资源均唯一命名并带归属标签，只删除自己创建的测试容器、卷和网络；修复“inspect 失败等于资源已删除”的误判，无法核实时会报清理失败，不假装清理成功。
- 新增独立 `Dockerfile.test` 和 `linux_tests.py`：只读、脱敏源码快照，关闭外网；开发镜像额外安装 Git/Node/Tesseract，生产镜像不因此增加这些系统工具。测试完成后移除临时快照和容器。
