## 为什么先看这个讲解

完成 Agent Memory Challenge 后，计划继续学习开源的 Pi Agent，并以此理解一个成熟 Agent 项目的工程结构，最终搭建面向工业/CAD场景的生产级 Agent。

费曼冬瓜的讲解被选作学习入口，不是为了只会使用 Pi，而是为了先获得一张源码阅读地图，再进入官方文档和代码仓库。

## 观看时重点关注的三个问题

截图中的三个主题是：

1. 如何维护 Agent 的循环：Trace、Turn、大事件钩子；
2. 如何进行上下文管理：截断、压缩、缓存命中率；
3. 如何维护工具调用：四阶段管道、错误回暖或错误恢复。

建议观看时不要只记录名词，而要追踪一条完整执行链：

```text
用户消息
  → 构造本轮上下文
  → 请求模型
  → 模型产生工具调用
  → 校验并执行工具
  → 写入工具结果
  → 再次请求模型
  → 形成最终回复或继续循环
```

## 需要从 Pi Agent 学到的内容

### Agent 循环

- 一轮模型请求在什么条件下继续或终止；
- 工具调用如何进入下一轮上下文；
- 如何限制最大步数、超时和费用；
- 用户如何中途修正或打断任务；
- 异常后如何恢复而不是丢失整条任务。

### Trace 与 Turn

- Turn 是一次用户、模型或工具交互单元；
- Trace 是一次完整任务的执行轨迹；
- 事件钩子用于记录模型调用、工具开始、工具结束、错误与状态变化；
- Trace 后续可以用于调试、评测、审计和失败案例复盘。

### 上下文管理

- 哪些消息必须保留原文；
- 哪些内容可以压缩；
- 工具输出过长时如何截断；
- 如何在压缩后保留任务目标、关键事实和未完成事项；
- 缓存如何降低重复模型调用和相同输入的处理成本。

### 工具系统

- 工具 schema 如何定义；
- 参数如何校验；
- 工具是否具有读取、写入或高风险权限；
- 执行结果如何标准化；
- 超时、重试、幂等和人工审批如何实现。

## 不直接照抄 Pi 的原因

Pi 更适合作为 Agent 工程的参考骨架，不应被误认为开箱即用的工业生产系统。工业 Agent 还需要补齐：

- 用户身份与数据隔离；
- 最小权限和高风险操作审批；
- 日志、链路追踪、成本监控；
- Prompt Injection 与恶意文档防护；
- 重试、幂等、队列和任务恢复；
- 离线评测集与版本回归；
- 模型降级、服务熔断和密钥管理；
- CAD操作前后的几何及工程约束校验。

## 与后续工业 Agent 的关系

计划中的工业/CAD Agent 可以形成如下闭环：

```text
用户需求、图纸、CAD模型
          ↓
Agent任务规划与知识检索
          ↓
调用特征识别、CAD生成等专业工具
          ↓
CAD内核执行与几何验证
          ↓
失败诊断、修改计划、重新执行
          ↓
输出模型、证据、执行轨迹和人工确认点
```
