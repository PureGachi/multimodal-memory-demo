# Agent 循环、上下文管理、长期记忆与工具调用

记录日期：2026-10-01

## 核心结论

上下文管理与 Agent Memory Challenge 关联很大，但二者不是同一个概念：

> 上下文管理决定模型这一轮看到什么；长期记忆决定跨越多轮和长时间后，系统应该保存、更新和找回什么。

完整的记忆 Agent 至少包含三层：

```text
第一层：Agent循环
Trace、Turn、事件、异常、重试、工具调用

第二层：上下文管理
分段、压缩、截断、预算、缓存、证据编排

第三层：长期记忆
写入、更新、冲突、遗忘、检索、重排
```

比赛主要通过 Add/Search 评价第三层，但第三层效果高度依赖前两层。

## 四个概念的边界

### Agent 循环

Agent 循环控制系统怎样反复执行：

```text
接收目标
  → 调用模型
  → 产生工具调用
  → 执行工具
  → 观察结果
  → 更新状态
  → 继续行动或结束
```

它关心控制流、终止条件、错误恢复和执行状态。

### 上下文管理

上下文管理控制下一次模型请求携带的内容，包括：

- 当前任务目标；
- 最近对话；
- 工具调用与关键结果；
- 从长期记忆中检索出的证据；
- 系统规则与权限；
- 当前剩余 token 预算。

它关心的是有限窗口中的信息选择与编排。

### 长期记忆

长期记忆保存不能始终放在上下文窗口里的历史信息，包括：

- 原始对话和图像；
- 事件摘要；
- 稳定事实和用户偏好；
- 信息更新、冲突和撤回；
- 已完成任务的经验与结果。

它关心跨会话、跨任务的信息持续性。

### 工具调用

工具调用使 Agent 能够接触模型之外的世界，例如：

- 向量数据库和关键词检索；
- OCR和视觉模型；
- reranker；
- 文件与数据库；
- CAD API和几何内核；
- 评测器和部署服务。

它关心能力执行、权限边界和结果反馈。

## 与比赛 Add 的关系

比赛的 Add 不是简单地把每条消息分别向量化。对于一段图文历史，需要处理：

- Turn 是否属于同一事件；
- 图片、caption和后续纠正如何绑定；
- 新事实是新增、修改、冲突还是撤回；
- 哪些内容值得形成长期记忆；
- 原始记录、摘要和结构化事实如何共同保存。

推荐的分层存储：

```text
原始记录层
├─ 原始Turn
├─ 原图
└─ 官方caption

事件层
├─ 事件摘要
├─ 时间范围
└─ 参与实体

事实层
├─ 事实内容
├─ 来源
├─ 有效时间
├─ 置信度
└─ 当前状态

检索层
├─ 文本Embedding
├─ 图像Embedding
├─ 关键词
└─ 元数据索引
```

## 与比赛 Search 的关系

Search 应完成的链路：

```text
用户问题
  ↓
查询理解与改写
  ↓
文本、图像、关键词等多路召回
  ↓
去重、时间过滤与冲突处理
  ↓
重排
  ↓
上下文预算分配
  ↓
返回有限、相关、可追溯的证据
```

上下文管理决定：

- 返回多少条证据；
- 返回原文、摘要还是两者组合；
- 是否保留相邻 Turn；
- 图片证据占用多少预算；
- 多跳问题如何组合多个事件；
- 新旧事实冲突时怎样排序和标注。

## 截断、压缩与长期记忆

简单截断：

```text
窗口过长 → 删除最早消息
```

这对长期记忆任务很危险，因为问题可能询问很久以前的信息。

更合理的方式是：

```text
原始数据完整保存
      ↓
事件级压缩
      ↓
事实与关系提取
      ↓
Search时按问题选择合适粒度
```

不同问题应返回不同层次：

- 精确原话问题：原始 Turn；
- 长期偏好问题：结构化事实；
- 事件经过问题：事件摘要和相邻记录；
- 图片内容问题：图片、caption、OCR和视觉描述；
- 信息变化问题：带时间的多个事实版本。

## 缓存与多模态记忆

图片处理成本较高，可按内容哈希缓存：

```text
image_hash
├─ 官方caption
├─ OCR结果
├─ 视觉模型描述
├─ 图像Embedding
└─ 处理模型与版本
```

还可以缓存查询 Embedding、query rewrite和候选集合。但缓存必须绑定版本和记忆状态，避免信息更新或删除后仍返回陈旧结果。

## 工具调用如何服务记忆系统

一次 Search 可能调用多个工具：

```text
查询解析器
  → 向量检索
  → BM25检索
  → 图像检索
  → 元数据过滤
  → Reranker
  → 证据打包器
```

每个工具需要记录：

- 输入和输出 schema；
- 开始、结束和耗时；
- 超时和错误类型；
- 是否可以重试；
- 结果来源和版本；
- 是否命中缓存。

这些 Trace 是后续做错误分析和评测的基础。

## 国庆 baseline 的合理范围

第一版不追求完整的自动记忆治理，优先完成：

1. 保留原始 Turn 和图文顺序；
2. 图片与 caption 正确绑定；
3. 同时索引原文、caption和事件摘要；
4. Search 后进行重排并限制证据预算；
5. 记录 Add/Search 的完整 Trace；
6. 对图片描述和 Embedding 做内容哈希缓存；
7. 用固定小型评测集测试召回、冲突和图文问题。

第一版的完成标准：

> 原始记录不丢失，重要信息能够压缩，问题相关的文字或图片证据能够准确进入有限上下文。

## 与后续工业 Agent 的迁移

竞赛中形成的模块可以直接迁入工业 Agent：

- Trace：用于生产调试和审计；
- Turn与事件聚合：用于长任务状态管理；
- 长期记忆：用于积累用户偏好、项目知识和历史案例；
- 上下文预算：用于控制成本与稳定性；
- 工具管道：用于接入 CAD、数据库和企业系统；
- 证据来源：用于工业场景中的可信回答与责任追踪。

因此，本次比赛并不是与工业 Agent 分离的一次练习，而是在训练其中的记忆、上下文和评测子系统。
